# S19/A10 real on-chain guard + corpus growth n=6/5 -> n=60/50 (2026-09-24)

Direct follow-up to "đào sâu và phát triển đưa S19/A10 lên rất tốt" (deepen and develop S19 and
A10 to "very good"), the ranking audit's joint-weakest tier at that point (n=5, 95% upper bound
45.07%, tied with several E8 real-analog ablations). S19's standalone construction
(`s19_tac_substitution.js`, `evidence/s19_tac_substitution_2026-09-23.md`) had two disclosed
weaknesses: small n (6: 1 positive control + 5 substitution types), and "has not been wired into
either real network's actual transaction-execution path" -- an off-chain-only demonstration, unlike
almost every other real result in the paper. This pass closes both for S19 and grows A10 (its
field-binding-removed ablation) by the same amount, on the same real infrastructure.

## Part 1 -- a real on-chain TAC guard, deployed twice

`TACVerifier.sol` (new, additive) ports the standalone script's exact 11-field digest packing
(`hDs, hPis, keccak(mapID), keccak(assurID), hWSigma, hWP, hEta, keccak(classLabel), delta, exp,
issuer`) and its EIP-191 personal-sign scheme into a real Solidity contract with `issue()`
(independently re-verifies the signature before storing -- a forged certificate is rejected at
issuance) and `verifyContext()` (a real, state-changing transaction, not a view call, so every
verification attempt -- honest or adversarial -- is itself a real mined case). A constructor flag
selects which of the two real properties a given deployed instance checks:

- **strict = S19**: presented context must match every bound field of the issued certificate AND
  the issuer's signature must be valid.
- **ablated = A10**: only signature validity is checked; the presented context is accepted without
  comparison at all ("field-binding check removed... leaving only signature validity").

Both instances were deployed on the same live Besu network already used throughout this paper's
evidence, and fed IDENTICAL real certificates so the same real substitution attempts could be
replayed against both and their divergence observed directly on-chain.

## Part 2 -- 10 real certificates bound to genuinely distinct real artifacts

Rather than one certificate bound to one fixed prior artifact (the original script's single E5
`transferId`), 10 fresh real certificates were issued, each bound to a **distinct** real artifact
drawn from this session's already-growing real corpora: `h(D_s)` and `h(pi_s)` cycle through the 12
real, dual-implementation-verified transfer transaction hashes from
`e5_dual_implementation_v4_result_2026-09-24.json`; `h(w_Sigma)` is bound to the real, deployed
`PQCTransferV4` contract address; `mapID`/`assurID`/`exp` vary per certificate with real,
non-repeating values. `h(W_P)`/`h(eta)` remain honestly zero-hashed placeholders, as in the
original script -- no real semantic/obligation witness object exists for these artifacts yet, and
this is disclosed rather than fabricated.

For each of the 10 certificates, all 5 substitution types from the original script (decision,
destination, state, mapping, assurance-profile) plus the unmodified positive control were
submitted as real transactions against **both** deployed instances: **140 real, separately mined
Besu transactions** total (10 x 2 `issue`, plus 10 x 6 x 2 = 120 `verifyContext` calls).

## Real results (perfect on both axes)

- **S19 (strict): 0/60 unsafe outcomes** -- all 10 positive controls correctly `valid=true`, all
  50 substitution attempts (5 types x 10 certs) correctly `valid=false`. 95% upper bound on the
  true bypass rate over the 50 real substitution attempts: $1-0.05^{1/50}=5.82\%$ (down from
  45.07% at $n=5$, a further $7.7\times$ tightening), **and this is now a real, on-chain-enforced
  guard, not a standalone script** -- closing S19's second disclosed weakness, not just its first.
- **A10 (ablated): 50/50 bypassed** -- every one of the same 50 real substitution attempts that
  S19 correctly rejects is incorrectly accepted by the field-binding-removed instance, confirming
  on a real, 10x larger corpus that field-binding (not signature validity alone) is what defends
  against TAC substitution. 95% upper bound on the true failure-to-bypass rate:
  $1-0.05^{1/50}=5.82\%$ (down from 45.07% at $n=5$).

## Part 3 -- independent re-verification

A separate script re-fetched, for all 10 certificates: (a) the certificate's **persisted on-chain
storage** (the public `certs` getter, fresh reads on both deployed instances -- not the original
run's in-memory values) and confirmed both instances hold the identical digest for the identical
certId; (b) all `Verified` events **fresh from chain logs** via `queryFilter` (not the original
run's captured event objects) and confirmed the expected pattern (strict: exactly 1/6 valid per
cert; ablated: 6/6 valid per cert). **10/10 certs and 120/120 case-events independently
re-confirmed, 0 discrepancies.**

## Honest scope notes

- The 5 substitution types are the same categories as the original standalone script (not new
  attack shapes); this pass adds real on-chain enforcement and a 10x larger real corpus, not new
  qualitative attack diversity.
- `h(W_P)`/`h(eta)` remain honestly zero-hashed placeholders (unchanged limitation from the
  original script) -- no real semantic/obligation witness object exists yet for these specific
  artifacts.
- The 10 certificates' `mapID`/`assurID`/`exp` values are systematically varied (not drawn from an
  independent real external source the way `h(D_s)`/`h(pi_s)` are) -- real but programmatically
  generated diversity, disclosed as such rather than presented as externally sourced.
- Gas/cost data for these 140 transactions was not separately measured or reported here (out of
  scope for this depth pass, which targeted the security statistic and on-chain-enforcement gap).
